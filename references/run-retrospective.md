# 每次查询的经验复盘

每次调用均生成，成功与失败都保留；一次批量任务共用一份，条目注明对应航司/航班。用于让下一次查询复用已验证路径，也让维护者能判断哪些规则值得纳入技能。

## 保存与交付

- 与本次 `汇总.md` 一起写入独立查询目录，文件名为 `经验复盘.md`；两份文档使用相对链接互链，最终回复给可点击链接并简述新增经验。文件写入不可用时直接在回复中输出内容，注明未落盘。
- 查询早停、没有浏览器或全程失败也写：停在哪里、实际报错、做过什么、仍缺什么。需用户操作时先交付当前复盘；同次接续后更新原文件，保留原阻塞与最终结果。
- 运行中只记关键失败、有效修正及已采用的捷径，收尾整理；不为写复盘重新访问站点、重演失败或额外采集全页数据。
- 保留可复现所需的环境、时间、入口路径和局部选择器；脱敏会话 URL，不记录 cookie、令牌、账户信息或完整 DOM。默认使用查询时区，时间采用带时区的 ISO 8601。

## 内容模板

无新发现的部分可合并成一句话；以下结构用于覆盖关键信息，不要求凑条数。

```markdown
# 航班全价票查询：经验复盘

- 采集时间与时区：实际记录
- 航司/站点/请求目标：实际目标，日期及航段
- 浏览器工具/版本/运行方式：可获取则记录，不知道就写未获取
- 结果：成功项、失败项与当前阻塞；实际生成时链接到同目录的汇总.md
- 经验来源：本次现场观察 / 用户转述 / 历史规则复用

## 踩坑与有效修正

| 目标/步骤 | 实际症状或报错 | 定位依据 | 修正动作 | 验证结果与适用范围 |
|---|---|---|---|---|

无新坑时写“本次无新增经验”，并注明复用过且本次有效的规则。
未经验证的原因写“推测”，未执行的修正写“待验证”；失败修正也保留结果。

## 省 Token 与操作效率

- 本次实际采用的局部读取、会话复用或动作+验证批处理。
- 可避免的重复调用/截图及下次改法；只在有日志或计数时填写实际数量。
- 没有 Token 统计就写“未采集 Token 数据”，不估算节省百分比。

## 下次最短路径

仅列本次验证有效的操作、关键校验点和停止条件。
未跑通时只写已验证到哪一步，后续路径标“待验证”。

## 待改进项

每项注明建议落点（航司条目 / 工具笔记 / 主流程）、依据及是否需复测。
没有新建议时写“无”；不将建议表述成已经修改的技能。
```

## 如何纳入后续版本

普通取价任务只产出复盘；用户要求优化技能时再审阅、去重、修改并验证。站点交互直接融入现有航司条目，工具 API/进程问题进入工具笔记，跨航司的取证约束才进入主流程；不为每次具体经验另建维护文件。

历史选择器须附适用站点、日期和来源；单次工具行为不推广成所有宿主的规定。来自用户的运行记录可以沉淀为线索，但没有原始截图或本次复测时，不新增“官网实测通过”声明。多条经验有冲突时，按当前页面及工具能力核验，保留不确定性。
