# 浏览器自动化排障手册(2026-10-21 实战踩坑沉淀)

> 适用:web-access CDP proxy、Playwright MCP、chrome-devtools MCP 等任何浏览器工具。
> 边界:只收录**诊断与操作类**经验;凡涉及"绕过控件校验、强填隐藏字段、强制提交"的做法一律不用(证据政策见 SKILL.md)。

## 1. eval 中文常量乱码(最隐蔽,先查传输层)

- **症状**:`innerText` 明明包含"按航班号查询",但 `includes('按航班号')` 恒为 false;按中文文本找元素永远找不到。输出里中文显示正常,极易误判为 shadow DOM、页面抖动或零宽字符反爬。
- **原因**:POST body 里的 UTF-8 中文可能被传输层按 GBK 类编码解码损坏,`\uXXXX` 转义一并损坏。
- **解法**:eval 内用码点构造中文再匹配,如 `String.fromCharCode(0x6309,0x73ED)` 拼"按班"。
- **验证(10 秒)**:字面量匹配不中、码点构造能中 → 传输层问题实锤,立刻改写全部中文常量,别再怀疑 DOM。

## 2. clickAt / 坐标点击漂移

- **症状**:eval 里量得元素在 (700,560),clickAt 却报 "clicked at (713,330)",点到隔壁选项/输入框(实测"北京"被点成"三亚")。
- **原因**:clickAt 内部先 scrollIntoView 再算坐标,两次滚动之间的时序差导致落点错位;页面越长越易触发。
- **解法**:定位与点击放**同一个 eval**——重新取 `getBoundingClientRect()` → `el.focus()` → 依次派发 mousedown→mouseup→click(带正确 clientX/Y)。clickAt 返回坐标与 eval 量到的坐标对不上时,弃用 clickAt。
- **边界**:该技巧只用于点击**已确认是目标**的元素;不得用于规避控件校验(见 SKILL.md 证据政策)。

## 3. "clicked:true" ≠ 命中目标

- **症状**:全屏弹窗遮罩没关时,点价格格每次都报成功,展开毫无反应。
- **解法**:点击无反应的第一步是**截图看遮罩**;用正常关闭控件("继续"/"我知道了"/×)关掉弹窗再操作。

## 4. 先截图,再猜

- 任何"点了没反应/内容找不到"**连续两次**尝试失败,立即截图看真实渲染,不要叠加 shadow DOM/页面抖动/零宽字符之类无证据的假设。历史统计:最大的时间浪费都发生在"不截图瞎诊断"阶段;截图还多次直接暴露表单真实状态(城市被写错等)。

## 5. 控件回写重置(按证据政策处理)

- **症状**:程序化给日期框设值后,日历控件又把值改回今天;城市面板写错框。
- **政策**:不抢在控件更新前提交、不强填隐藏字段(见 SKILL.md)。正确做法:**接受控件最终值,以结果页实际数据为准记录**,截图注明"实际查询日期",汇总表里区分"请求日期"与"实际查询日期"。

## 6. 表单 POST 整页跳转,没有 XHR

- **症状**:点查询后等结果容器、查 `performance` 里的 XHR,全空,误判为没提交。
- **解法**:先读 `form.action` / `form.method` 判断提交方式;整页跳转型(如 `flightDynamicResult.do`)提交后**等新文档加载**,不要傻等异步结果出现。

## 7. 后台 tab 截图超时

- `Page.captureScreenshot` 对后台页偶发超时(浏览器后台节流):直接重试即可,不必换方案。

## 8. 稳定操作顺序(总结)

1. `check-deps` → 打开页面 → **先截一张初始图**确认真实状态;
2. 中文匹配一律码点构造;
3. 点击用"单 eval 内 focus + 事件序列"(工具原生 click 优先);
4. 点击无反应 → 查遮罩弹窗 → 再不行读表单 action 判断提交方式;
5. 控件改值不受控时,按证据政策如实记录控件最终值;
6. 每步产出物(截图/文件)交付前先目检。
